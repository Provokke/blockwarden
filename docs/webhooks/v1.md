# Blockwarden webhook payload, version 1

This is a public interface. It changes only with a major version of `@blockwarden/relayer-client` and a new
number in `specVersion`. Fields are only ever added inside a version; nothing is removed or retyped.

## Request

`POST` to the URL on the action, with `content-type: application/json`, from an AWS Lambda function in the
operator's own account. Redirects are not followed, so the URL has to be the final one. Only `https` is accepted.

| Header | Value |
|---|---|
| `X-Blockwarden-Signature` | `t=<unix seconds>,v1=<hex HMAC-SHA256 of "<t>.<raw body>">`. Several `v1=` values appear while a secret is rotating; any one of them matching is a valid signature. **The timestamp lives here, in `t`. There is no separate timestamp header.** |
| `X-Blockwarden-Delivery` | The delivery id, the same string as `id` in the body. Use it to ignore a delivery you have already handled. |
| `User-Agent` | `Blockwarden/1` |

A webhook action may rename both headers (`signatureHeader`, `deliveryHeader`), so a receiver sees its own
product's name. The format of the values does not change.

`verifyWebhook()` accepts a timestamp **within 300 seconds** of now, in either direction, and that is what the
sender's own tests assert. A receiver that sets its own tolerance should not go above 900 seconds: a delivery
that has waited longer than that has been retried, and its `t` is the time of the attempt, not of the event.

## Body

```json
{
  "id": "dlv_9a1c...",
  "type": "match.final",
  "createdAt": "2026-09-20T10:19:03.114Z",
  "specVersion": 1,
  "data": { }
}
```

| Field | Type | Meaning |
|---|---|---|
| `id` | string | The delivery id, `dlv_` and 32 hex characters. Unique per attempt-group: every status change gets its own id, so a transaction that is reorged out and mined again sends a second `tx.mined` with a **different** id. Retries of one delivery reuse the id. |
| `type` | string | `match.provisional`, `match.final`, `match.dropped` or `tx.<status>` where status is one of `queued`, `submitted`, `mined`, `confirmed`, `failed`, `cancelled`. |
| `createdAt` | string | When the delivery was created, not when this attempt was sent. ISO 8601 with milliseconds, always UTC. |
| `specVersion` | number | `1`. Absent only from a body sent by a version of Blockwarden older than this document. |
| `data` | object | The event body, below. |

### `data` for `match.*`

Every numeric value inside `args` is a **decimal string**, because a uint256 does not fit in a JSON number.
Numbers that are always small — `chainId`, `blockNumber`, `logIndex`, `ordinal` — are JSON numbers.

| Field | Type | Notes |
|---|---|---|
| `matchKey` | hex string | `keccak256(chainId, transactionHash, ordinal, ruleId)`. Stable across a provisional record and its final one. |
| `ruleId` | string | |
| `status` | `provisional` \| `final` \| `dropped` | |
| `chainId` | number | |
| `address` | hex string | The contract that emitted the log, lowercase. |
| `transactionHash` | hex string | |
| `blockNumber` | number | |
| `blockHash` | hex string | The block the log was recorded in. A provisional record's block can differ from its final one's. |
| `logIndex` | number | Within the block. |
| `ordinal` | number | The log's position among the logs of the same transaction, block and rule. |
| `event` | string | The rule's event signature, for example `event Transfer(address indexed from, address indexed to, uint256 value)`. |
| `eventName` | string | `Transfer`. |
| `args` | object | Decoded arguments by name. A tuple is an object, an array is an array, and both nest. Addresses and bytes are hex strings, `bool` is a JSON boolean, every integer is a decimal string. |
| `firstSeenAt` | string | When the match was first recorded. |
| `finalizedAt` | string \| null | When it became final; `null` while provisional or dropped. |

A `fast` rule sends `match.provisional` when the log is first seen in an unfinalized block, then exactly one of
`match.final` or `match.dropped`. A `finalized` rule sends only `match.final`. A dropped match's log was reorged
away, and nothing it described happened.

### `data` for `tx.*`

The transaction exactly as `GET /v1/relayer/txs/{txId}` returns it: `txId`, `kind`, `signerId`, `chainId`,
`from`, `to`, `data`, `value`, `gasLimit`, `status`, `nonce`, `hash`, `blockNumber`, `blockHash`,
`receiptStatus`, `error`, `revertData`, `fillerTxId`, `idempotencyKey`, `reference`, `dependsOn`, `createdAt`,
`updatedAt`. `value` and `gasLimit` are decimal strings. `receiptStatus` is `success` or `reverted` once the
transaction is mined, and `null` before that. `reference` is the caller's own string, echoed. `revertData` is
the raw revert data when the transaction failed because its call reverts.

Use `isTxEvent(event)` and `parseTx(event.data)` from `@blockwarden/relayer-client` to read one with bigints.

## Answering

Answer `2xx` and nothing is retried. Any other status, or no answer at all, is an attempt that failed:

- `4xx` other than `429` is permanent. The delivery is dead-lettered at once, with no further attempt.
- `429` and `5xx` are retried, as are a timeout, a connection failure and a TLS failure.
- Up to **8 attempts**, about 10 s, 30 s, 90 s, 270 s, 810 s, 900 s and 900 s apart with jitter, then dead-lettered.

The body of the answer is read only for an operator's logs, at most 2 KB of it. A redirect is an attempt that
failed; it is never followed.

## What is not guaranteed

The delivery is **at least once**. A crash between claiming a delivery and sending it, an SQS redelivery, or the
reaper picking up a delivery whose attempt is still in flight can all send the same body twice with the same
`X-Blockwarden-Delivery`. Dedupe on that header. Two different deliveries never share an id.

Order is not guaranteed either. `match.final` can arrive before `match.provisional` if the first attempt of the
provisional one failed. Compare `data.status`, not arrival order.
